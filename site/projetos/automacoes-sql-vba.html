Visão geral

Scripts SQL e macros VBA para produtividade no dia a dia de migração e consultoria: deduplicação de dados, extração direcionada e validação estrutural de planilhas antes da carga.

Problema resolvido

Tarefas repetitivas de verificação e limpeza de dados (checar formato de planilha, remover duplicidade de CPF, extrair responsáveis de uma base) consomem tempo manual e são propensas a erro humano quando feitas "na mão".

Contexto

Esses scripts foram criados ao longo de diferentes projetos de migração e consultoria, como ferramentas de apoio pontuais — uma caixa de ferramentas reutilizável para acelerar etapas específicas do processo.

Minha atuação

  • Escrita de scripts SQL para eliminação de duplicidade de contatos e de CPF em bases migradas.
  • Escrita de scripts SQL de extração direcionada (ex.: extração de responsáveis).
  • Desenvolvimento de macros VBA para validar, aba a aba, se uma planilha de migração segue a estrutura esperada pelo Legal One.

Tecnologias utilizadas

SQL Server (T-SQL) VBA Excel

Solução implementada

Scripts SQL de deduplicação e extração:

  • elimina_duplicidade_contatos.sql e tira_duplicidade_cpf.sql — identificam e tratam registros duplicados por CPF antes da carga final.
  • extrai_responsaveis.sql — consulta direcionada para extrair a relação de responsáveis de uma base de origem.

Validador de planilha em VBA: um conjunto de ~7 macros (CONFERE_CONTATOS.VBA e correlatos) percorre cada aba de uma planilha de migração padrão e compara a estrutura de colunas com o padrão esperado, sinalizando divergências antes do envio para carga.

Processo técnico

Planilha de migração preenchida
  └─> Macro VBA percorre cada aba
       └─> Compara colunas encontradas x estrutura esperada
            └─> Sinaliza divergências antes do envio para carga

Base de origem (concorrente) ou já migrada
  └─> Script SQL de deduplicação / extração direcionada
       └─> Base tratada, pronta para a próxima etapa

Desafios e decisões

  • Padronização sem sistema central: scripts simples e diretos priorizaram velocidade de entrega.
  • Validação antecipada: o validador VBA foi pensado para pegar erros de estrutura antes da carga, evitando retrabalho.

Overview

SQL scripts and VBA macros for day-to-day productivity in migration and consulting: data deduplication, targeted extraction, and structural spreadsheet validation before loading.

Problem solved

Repetitive data-checking and cleanup tasks (checking spreadsheet format, removing duplicate tax IDs, extracting responsible parties) consume manual time and are prone to human error when done by hand.

Context

These scripts were created across different migration and consulting projects as targeted support tools — a reusable toolbox to speed up specific process steps.

My role

  • Writing SQL scripts to eliminate duplicate contacts and duplicate tax IDs in migrated databases.
  • Writing targeted SQL extraction scripts (e.g., extracting responsible parties).
  • Developing VBA macros to validate, sheet by sheet, whether a migration spreadsheet follows the structure expected by Legal One.

Technologies used

SQL Server (T-SQL) VBA Excel

Solution implemented

Deduplication and extraction SQL scripts:

  • elimina_duplicidade_contatos.sql and tira_duplicidade_cpf.sql — identify and treat duplicate records by tax ID before the final load.
  • extrai_responsaveis.sql — targeted query to extract the list of responsible parties from a source database.

VBA spreadsheet validator: a set of ~7 macros (CONFERE_CONTATOS.VBA and related files) walks through each sheet of a standard migration spreadsheet and compares the column structure against the expected standard, flagging discrepancies before submission for loading.

Technical process

Completed migration spreadsheet
  └─> VBA macro walks through each sheet
       └─> Compares found columns against expected structure
            └─> Flags discrepancies before submission for loading

Source database (competitor) or already-migrated database
  └─> SQL deduplication / targeted extraction script
       └─> Treated database, ready for the next process step

Challenges and decisions

  • Standardization without a central system: simple, direct scripts prioritized delivery speed.
  • Early validation: the VBA validator was designed to catch structural errors before loading, avoiding rework.
