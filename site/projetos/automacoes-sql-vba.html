      SQL Server VBA Excel

      Visão geral

      Scripts SQL e macros VBA criados ao longo de projetos de migração e consultoria para acelerar tarefas repetitivas: deduplicar contatos, extrair dados de forma direcionada e validar a estrutura das planilhas antes da carga. Fazer isso “na mão” consome tempo e abre espaço para erro humano.

      Minha atuação

      • Scripts SQL de deduplicação de contatos e de CPF em bases migradas.
      • Scripts SQL de extração direcionada (por exemplo, a relação de responsáveis de uma base).
      • Macros VBA que validam, aba a aba, se a planilha de migração segue a estrutura esperada pelo Legal One.

      Como funciona

      O validador percorre cada aba da planilha de migração, compara as colunas com o padrão esperado e sinaliza divergências antes do envio para carga, evitando que erros de estrutura só apareçam na importação.

      Planilha de migração preenchida
  └─> Macro VBA percorre cada aba
       └─> Compara colunas encontradas x estrutura esperada
            └─> Sinaliza divergências antes do envio para carga
Base de origem (concorrente) ou já migrada
  └─> Script SQL de deduplicação / extração direcionada
       └─> Base tratada, pronta para a próxima etapa

      Overview

      SQL scripts and VBA macros created across migration and consulting projects to speed up repetitive tasks: deduplicating contacts, running targeted extractions, and validating spreadsheet structure before loading. Doing this by hand takes time and leaves room for human error.

      What I did

      • SQL scripts to deduplicate contacts and tax IDs in migrated databases.
      • Targeted SQL extraction scripts (for example, the list of responsible parties in a database).
      • VBA macros that validate, sheet by sheet, whether the migration spreadsheet follows the structure Legal One expects.

      How it works

      The validator walks through each sheet of the migration spreadsheet, compares the columns with the expected standard, and flags discrepancies before submission for loading, so structural errors don't surface only at import.

      Filled-in migration spreadsheet
  └─> VBA macro walks through each sheet
       └─> Compares found columns x expected structure
            └─> Flags discrepancies before submission for loading
Source database (competitor) or already migrated
  └─> SQL deduplication / targeted extraction script
       └─> Treated database, ready for the next step

      Challenges and learnings

      • Early validation: the VBA catches structural errors before the load, avoiding rework.
      • Speed vs. standardization: simple, direct scripts prioritized delivery, without a central system.
      • Next steps: gather the scripts in a single library and add tests for the SQL ones.
