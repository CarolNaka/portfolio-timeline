      Consultoria Recorrente em Banco de Dados

      Ajustes pós-migração no Legal One, com segurança operacional

      Recurring Database Consulting

      Post-migration adjustments in Legal One, with operational safety

      Consultoria Consulting SQL Server Legal One

      Visão geral

      Suporte recorrente a clientes já migrados para o Legal One: correções e ajustes direto no banco de produção para o que a interface não resolve, como dados incorretos, regras específicas e baixa em massa de processos. Por ser uma operação de risco, todo caso segue o mesmo padrão: aprovação formal por e-mail e plano de reversão (rollback) pronto antes de executar.

      Minha atuação

      • Interpreto a solicitação do cliente e a traduzo em escopo técnico.
      • Escrevo scripts SQL sob medida: correção de dados, baixa de processos, centro de custo, tipo de ação e reorganização de objetos.
      • Rodo o script de diagnóstico antes de qualquer alteração e só executo em produção após a aprovação formal.
      • Preparo o script de rollback de cada ajuste antes de executá-lo.

      Como funciona

      Cada demanda segue um padrão de 3 scripts:

      • Declarativo: lista exatamente quais registros serão afetados, sem alterar nada, e serve de base para a aprovação.
      • Execução: aplica a alteração já validada em produção.
      • Rollback: reverte a alteração; é preparado antes da execução, não depois.

      Assim, uma operação arriscada vira um processo auditável e reversível.

      Solicitação do cliente (e-mail)
  └─> Script declarativo (diagnóstico / escopo do impacto)
       └─> Aprovação formal por e-mail
            └─> Script de execução (update em produção)
                 └─> Script de rollback já preparado (plano de reversão)

      Desafios e aprendizados

      • Risco em produção: o rollback preparado antes de executar mitiga o risco de forma sistemática.
      • Demandas diversas: cada cliente traz uma regra de negócio diferente, que exige leitura cuidadosa antes de virar SQL.
      • Rastreabilidade: a aprovação por e-mail mantém o histórico de quem autorizou o quê.
      • Próximos passos: transformar ajustes recorrentes em templates parametrizáveis e reunir os casos em um repositório único.

      Overview

      Recurring support for clients already migrated to Legal One: fixes and adjustments made directly in the production database for what the interface can't solve, such as incorrect data, specific rules, and bulk case closing. Because this is a risky operation, every case follows the same standard: formal email approval and a rollback plan ready before running.

      What I did

      • I interpret the client's request and translate it into technical scope.
      • I write tailored SQL scripts: data fixes, case closing, cost center, case type, and object reorganization.
      • I run the diagnostic script before any change and only execute in production after formal approval.
      • I prepare the rollback script for each adjustment before running it.

      How it works

      Each request follows a 3-script standard:

      • Declarative: lists exactly which records will be affected, changing nothing, and serves as the basis for approval.
      • Execution: applies the validated change in production.
      • Rollback: reverts the change; prepared before execution, not after.

      This turns a risky operation into an auditable, reversible process.

      Client request (email)
  └─> Declarative script (diagnosis / impact scope)
       └─> Formal approval by email
            └─> Execution script (production update)
                 └─> Rollback script already prepared (reversal plan)
