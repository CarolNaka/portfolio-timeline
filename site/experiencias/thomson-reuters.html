    Overview

    Tool developed in Python (Selenium + Tkinter) to automate the identification and merging of duplicate contacts in Legal One. It has its own graphical interface and is distributed as an executable, allowing consultants to run the procedure directly in the client's environment.

    The project came from spotting an operational bottleneck: in the traditional process, fixing duplicates required extracting the production database, treating it in staging, validating, and then scheduling the update in production. A long flow, dependent on the migration team and subject to service-level deadlines (SLA).

    With the tool, that flow is replaced by an automated run. The consultant only needs access to the client's environment and the spreadsheet with the identified contacts. From there, the program handles the rest: it identifies duplicate groups by tax ID (CPF/CNPJ), triggers Legal One's native merge feature, and generates a detailed log for checking during and after the run.

    Own idea, development, and authorship. The source code is not public; the architecture and how it works are documented in this presentation.

    What I did

    • I identified the operational bottleneck and conceived a solution to remove the migration team's involvement in this type of request.
    • I developed the automation in Python, initially using PyAutoGUI and later moving to Selenium.
    • I built an intuitive graphical interface with Tkinter, designed to be easy for consultants without programming knowledge to use.
    • I implemented execution logs to follow progress, spot issues, and check results during and after processing.
    • I packaged the application as a single executable with PyInstaller, making it easy to distribute and use.
    • I produced a training video to guide other consultants in using the tool.

    How it works

    The process was designed to require minimal intervention from the consultant. There is no need to prepare intermediate environments, run scripts manually, or forward the request to the migration team.

    • Environment access: the consultant starts the tool and logs in manually in the browser, using their own credentials.
    • Data input: loads the spreadsheet provided by the client with the contacts that need treatment.
    • Identification: the tool automatically groups duplicate contacts based on the tax ID (CPF/CNPJ).
    • Execution: for each identified group, it triggers Legal One's native contact-merge feature.
    • Checking: generates a detailed execution log, making it possible to follow the processing and verify the results afterwards.

    Operational flow:

    Spreadsheet provided by the client + environment access
→ Duplicate identification and grouping
→ Automated run of the native merge
→ Log generated for checking

    Challenges and learnings

    1. Automation scalability
      The first version used PyAutoGUI, based on screen coordinates and interactions. Besides scalability limits, execution depended on the visual interface and could not run properly in the background, tying the process to the availability of my own session. Moving to Selenium made it possible to interact directly with page elements and made the automation more flexible.
    2. Authentication and different environments
      One challenge was building an authentication approach that worked for different clients, considering access particularities and the differences between production and staging environments. The solution had to respect individual credentials and permissions, without relying on a global login.
    3. Choice of technical approach
      The solution uses interface automation instead of direct API integration. Although not the most sophisticated architecture, it was a pragmatic choice given the integration options available and the need to leverage Legal One's native merge feature.
    4. Limits and possible evolutions
      The automation depends on the structure and elements of Legal One's interface and requires maintenance if relevant changes occur. Currently, identification uses CPF/CNPJ. Possible evolutions include:
      • Identifying potential duplicates by name similarity and other attributes.
      • Intelligent data analysis to suggest potentially duplicate contacts, without interfering with use of the database.
      • Generating recommendations for the consultant to review, letting the client assess which contacts may be merged before any change.
      • API integration, if available and properly supported.
      • Collecting usage metrics to measure the tool's operational impact.
